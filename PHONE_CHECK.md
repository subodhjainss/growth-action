# Phone check

Open https://rapid-gull-487.convex.site on your phone, signed out and on mobile data. No real data is needed for this walkthrough. Browser checks at 390-pixel phone width have passed; a physical phone has not been tested by Codex.

1. Tap **Explore the demo**. Five entirely invented ad sets show scale up, reduce, hold and insufficient-evidence states. Open **Why?** to inspect calculations, uncertainty and the example-policy label.
2. Approve Everyday tees. Confirm **Approved** and **Awaiting next read** appear together. Nothing changes in Meta.
3. Open **Test tomorrow’s implementation states**. Try matching, changed differently and unchanged reads. See **Done as approved**, **Done differently** or **Not done yet** alongside the saved approval. These reads are simulated, not real account refreshes.
4. Open the menu → **History**, expand the saved decision and inspect recommended versus decided and dated observations. Reload, tap Explore the demo again and confirm the decision remains. Reset demo clears only invented demo state.
5. Return home. Enter https://example.com and tap **Understand my business** to see the loading/read/summary states. Unknown fields remain “Not confirmed yet”. Enter `Products: comfortable cotton tees` in the correction box, save it and confirm the displayed version changes without another screen.
6. Tap **Connect my ad account**. Create a private workspace with your own email and a new app password. Never enter a Meta password. The preferred connection tab explicitly says access is not configured; **Continue with CSVs** opens the working fallback.

## Other states

- Website error: try https://example.invalid; the error offers manual brand entry and preserves the address.
- Empty history: open History in a fresh/reset synthetic demo before deciding anything.
- No cards in a view: choose To review after recording decisions, or search for a name that does not exist. Clear the filter/search to restore cards.
- Wrong answer: Edit a supported demo card and give an amount/reason, or Reject it. History retains the original recommendation. Safety-blocked examples cannot be edited into an actionable approval.
- Missing evidence: inspect New arrivals and Studio collection. Their Why sections explain incomplete history and shared-budget limitations.
- Import error: choose a CSV without required numeric/date/identity fields. Correct/retry; an invalid package is not a successful assessment. Do not use confidential files for public screenshots.
- Saving/loading: visible messages describe actual requests; slower network settings make these easier to see. A failed save must retain the previous status.
- Unable to verify: covered by deterministic tests for missing/wrong-budget-object/stale observations; the synthetic UI does not currently offer a dedicated unknown-read simulator.

Real CSV persistence was browser-tested using invented files through signup → import → evidence → decision → reload → history. A later complete configuration import is required to infer real implementation. Read-only Meta refresh remains blocked by connection setup.
